# Working on Rubast

Rubast is a Ruby-written AOT compiler for a documented Ruby subset. It uses Prism, a Ruby semantic IR, Rust emission, and Cargo. This file is the starting point for agents and contributors. The implementation and executed checks are authoritative for current behavior; architecture documents also describe planned work.

Current pipeline: source bytes → Prism AST → normalized IR → validation → Rust source and runtime → Cargo binary. The CLI exposes `run` and `emit-rust FILE -o DIR`. `nil`, booleans, signed 64-bit integers, UTF-8 strings, top-level and method locals, `gets`, safe `chomp`, interpolation, `puts`, and user classes with constructors and scalar/object instance state form the current subset. Method bodies support expression sequences, local assignments, `puts`, last-expression returns, explicit `self.method`, and implicit instance calls. Arguments, results, and fields preserve object handles, including cycles retained until runtime teardown. Ordinary calls emit separate Rust functions specialized when resolved nested lookup differs; calls with literal blocks inline their validated method bodies. Scalar equality, integer comparisons, proven-safe `i64` arithmetic, scalar `if`/`unless`, and method `return` are supported. Branches and returns join types and field state. Empty classes, single user-class inheritance, inherited construction, overriding, and explicit/forwarded `super` are supported. Lookup uses the concrete receiver while `super` starts above the method owner; recursive calls remain unsupported. `while`/`until`, pre/post-test modifiers, `break`, `next`, plain `begin`, and local/instance compound arithmetic assignment are supported. Loop invariants recheck locals and object fields with bounded analysis and narrow direct integer-literal guard comparisons. Unbounded integer growth and fresh user objects in loops remain diagnostics. Arrays support literals, integer indexing, fixed indexed assignment, length, and push with shared arena identity and a 10,000-slot analysis limit. Nested arrays and cycles preserve aliases. Strings use shared mutable UTF-8 buffers with concatenation, append/replace/clear, dup/chomp/chomp!, and length/bytesize. Frozen mutations raise `FrozenError`; fresh arrays in loops remain diagnostics. Static symbols support scalar operations. Hashes support Symbol/single-valued Integer keys, lookup/assignment, key presence, length, keys/values arrays, insertion order, shared references, and cycles. Analysis caps hashes at 10,000 literal entries/distinct keys and 32 alternative orders; keys/values require a single order. String/custom/dynamic keys, hash equality/output, and fresh hash/keys/values allocations in loops remain diagnostics. Literal inline each/map/times blocks support zero/one positional parameter, explicit block locals, captured assignments, self, and fixed iteration shapes. Normalization uses a fresh session and respects Prism local depth; analysis/emission expand at most 1,000 block-body validations per compilation. Changing array lengths, fresh object/collection allocations in block bodies, nested map allocation, implicit/extended block parameters remain unsupported. User instance-method blocks and yield preserve lexical caller locals/self, isolated callee scope, argument order, block results, and captured-state joins across branches/returns/loops. Inlined method returns use their own labeled boundary. User methods and constructors accept named optional/rest/keyword/keyword-rest/block parameters. Defaults run at call time; splats snapshot caller slots and keyword groups preserve their distinction from positional hashes. Named literal blocks support call and forwarding through user methods, constructors, and super with original captures and exit targets. Missing yields/callbacks and invalid supported argument shapes raise Ruby runtime errors. Safe block calls, escaped blocks, anonymous forwarding, custom conversions, and Symbol-to-Proc remain diagnostics. Block break has a distinct target in semantic IR and exits its receiving iterator/method through a Rust label; normal and break paths join captured locals and fields. Empty/ignored/dead paths and loop solver trials discard exit records. Existing object-result joins and unchanged traversed-array lengths remain required on exit paths. Block next uses a distinct labeled boundary for each invocation; its value becomes a map element or yield result, while each/times continue. Analysis joins next and normal body states before copying captured bindings back. Ordinary methods clear block-next context, and dead/empty/ignored/speculative paths discard exit records. Block return retains its lexical defining method context through nested yield calls, reuses the existing Rust function/inline return boundary, and projects exit snapshots to that method’s locals and capture depth. Active method-return contexts participate in exit trimming alongside block contexts. Top-level/escaped returns and existing traversal/allocation/result-join limits remain diagnostics. `raise`/`fail`, built-in exception values, static rescue classes, else, ensure, rescue modifiers, implicit method/block handlers, and bounded rescue retry are supported. Structured `Outcome`/`Flow` results carry exceptions and control exits across cleanup boundaries; ordinary Rust returns/labels remain inside a boundary. Analysis joins exceptional and pending-exit state, preserving lexical scopes and captures. Runtime errors cover zero division/modulo, invalid negative array writes, and frozen-string mutations. Uncaught errors retain Ruby locations, first backtrace, causes, CRuby source snippets, and status 1. Retry state must converge within 16 passes; invalid block retry, custom/computed exception classes, broader exception APIs, backtrace/keyword raise arguments, and practical I/O faults remain outside this contract. Other constructs described in the architecture may still be proposals.


Stage 14 adds executed class/module bodies, lexical/qualified/absolute/inherited constants, class objects and aliases, inherited class methods with per-class instance fields, static include/extend/prepend, visibility, and static attr macros. Super resolves ancestor occurrences; setter assignment returns its right-hand side after evaluating both operands once. Static composition is limited to direct namespace-body calls on the current class/module object. Invalid visibility access, dynamic mutation, reopening, instance extension, composition callbacks, reassigned/computed constants, eigenclass body state, and compound attribute assignment remain diagnostics. Array concatenation and acyclic scalar/nested-array equality, nil?, and one-argument integer/boolean/nil p support the unchanged supplied registry. NilCheck retains dynamic emission and a proven predicate outcome for analysis. See README and stage 14 acceptance/boundary features for the exact contract.

## Invariants

1. **An accepted construct must behave like CRuby on its declared inputs.** A green parser or validator test does not establish runtime support. Add a Cucumber scenario that executes the generated program and compares stdout, stderr, and exit status with pinned CRuby before expanding the accepted subset.
2. **Unsupported semantics fail before Rust emission.** Preserve a diagnostic code and Ruby location. Do not drop a Prism node, substitute a value, or broaden validation merely to make compilation succeed.
3. **Stage ownership is explicit.** Prism syntax belongs in the frontend; Ruby meaning and supported-call rules belong in IR and analysis; the backend receives validated IR; Rust runtime behavior belongs in `runtime/rubast_runtime/`. Keep Ruby semantic rules out of Cargo execution.
4. **Dependency direction stays one-way.** `system/container.rb` assembles services from `app/`. Only the CLI resolves the top-level compiler. Services receive constructor dependencies; IR, diagnostics, and per-run data in `lib/rubast/` do not use the container.
5. **Compilation state is per run.** Do not memoize mutable state in container-managed services across compilations. The planned `CompilationContext` is not implemented yet.
6. **Preserve observable evaluation.** New expressions must maintain Ruby value, side-effect order, and error behavior. Use inputs that distinguish a correct translation from a plausible incorrect one.

## Change workflow

1. Locate the owner in [docs/development.md](docs/development.md). Capture the smallest Ruby repro and expected CRuby result.
2. For new observable behavior, write or use a Cucumber scenario first and run it red. For unsupported behavior, assert the diagnostic code and source location.
3. Implement in the owning stage. Add a focused RSpec example when it tests a pass decision or container wiring that the scenario cannot isolate.
4. Run the focused check, then `bin/verify` before reporting completion. This runs RuboCop, RSpec, Cucumber, Rust formatting, and Cargo tests. CI runs the same checks on pushes and pull requests.
5. Report which checks actually ran. Update the documented subset when support changes. A diagnostic removed without emitted execution evidence is not a completed feature.
6. Complete roadmap stages in order. After each stage passes `bin/verify`, commit its implementation, tests, and documentation and push it to GitHub before starting the next stage. Report the commit and push result; distinguish local checks from hosted CI status.

Write project documentation, Cucumber features, and Cucumber step definitions in English. Do not weaken a user-provided scenario or suppress a failing comparison to make a check green. Documentation-only edits need no new behavior test.
